# widgetsack — форк для личного Windows-дашборда

Форк [`gyng/widgetsack`](https://github.com/gyng/widgetsack) (`ixoid/widgetsack`). Прозрачный click-through
оверлей на втором мониторе плюс редактор Studio. Сверх апстрима в форке есть:

| Виджет / интеграция | Что делает | Где настраивается |
|---|---|---|
| **Camera** (C-1) | Живой RTSP-поток с LAN-камеры, декодирование внутри приложения (`retina` → WebCodecs), без go2rtc и сторонних процессов | Studio → Plugins → Camera |
| **Server check** (S-1) | Доступность VPS и локальных хостов: ICMP, TCP-порт, HTTP | Studio → Plugins → Server check |
| **Agenda+** (K-1) | Ближайшие события из ICS-календаря с группами и обратным отсчётом | Studio → Plugins → Agenda |
| **HWiNFO** (H-1) | Температура, частоты и мощность CPU из HWiNFO64 | Studio → Plugins → Hardware (HWiNFO) |
| **met.no** (W-1, W-2) | Провайдер погоды, работающий из РФ, с дневными экстремумами | Studio → Plugins → Weather |
| **CBR + Binance** (T-1) | Курсы ЦБ и крипта для тикеров (Yahoo Finance из РФ не отвечает) | Studio → Plugins → Stocks |
| **Notifications** (N-1) | Лента последних уведомлений Windows (приложение, заголовок, текст, время) — прочитать то, что прилетело во время игры | Studio → Plugins → Notifications |

Архитектура форка: `docs/dev/fork-architecture-notes.md`. Решения: `docs/decisions/`. Роадмап: `docs/PRODUCT_ROADMAP.md`.

## Установка боевой версии

1. Собрать инсталлер (или взять готовый из `dist/`): см. «Сборка релиза» ниже.
2. **Закрыть dev-оверлей**, если он запущен: правый клик по иконке в трее → Quit. Релиз и dev-сборка
   используют один и тот же конфиг `%APPDATA%\io.github.gyng\` и одну блокировку «один экземпляр», вторая копия
   просто не стартует.
3. Запустить `widgetsack_0.0.71_x64-setup.exe`. На последней странице инсталлера поставить галочку
   **Launch at login** — это и есть автозапуск (ключ `HKCU\…\Run`, приложение само восстанавливает его после
   каждого обновления). Переключить позже можно в Studio → Settings.
4. После первого запуска оверлей подхватит текущую раскладку и настройки плагинов из `%APPDATA%\io.github.gyng\`,
   ничего заново вводить не нужно. Если ставится на чистую машину — раскладка владельца лежит в
   `examples/layouts/own-desktop.widgets.json` (импорт через Studio), а все секреты (пароль камеры, ICS-ссылка)
   вводятся в Studio заново: в репозитории их нет и быть не может.

### Обновление

Собрать новый инсталлер, выйти из приложения через трей, запустить инсталлер поверх. Раскладка, настройки
плагинов и автозапуск сохраняются.

**Не ставить апстримные релизы поверх форка.** Studio → Settings → About умеет проверять обновления, но
смотрит на релизы `gyng/widgetsack`: у них тот же `productName` и идентификатор, инсталлер апстрима молча заменит
форк и все виджеты форка пропадут из раскладки. Проверку обновлений держать выключенной, новые версии
апстрима забирать через `scripts/sync-upstream.ps1` и пересобирать.

## Сборка релиза

Из корня репозитория, в PowerShell:

```powershell
.\scripts\release-fork.ps1
```

Скрипт собирает клиент и Rust в release-профиле, делает NSIS-инсталлер (без подписи) и кладёт копию в
`dist\widgetsack_0.0.71_fork-<дата>-<коммит>-setup.exe`. Нужны: Node 24, Rust stable MSVC, VS Build Tools 2022,
WebView2 (на Windows 11 есть). Первая сборка занимает 10–15 минут, последующие 3–5.

Перед сборкой релиза должны быть зелёными гейты (`client/`: `npm run check; npm run lint; npm run test:coverage;
npm run build`; корень: `cargo fmt --check; cargo test; cargo clippy --all-targets -- -D warnings`).

## Камера: что нужно знать

- Адрес вида `rtsp://<ip>:8554/ch2`, логин и пароль вводятся в Studio → Plugins → Camera. Поля write-only: после
  сохранения значения не показываются, пароль хранится зашифрованным DPAPI текущего пользователя и никогда не
  попадает в webview, лог или файл в открытом виде. Смена адреса или порта сбрасывает сохранённые логин и пароль.
- **Test connection** делает один DESCRIBE и показывает кодек и размер кадра. Три неудачных логина подряд не
  бывает: после 401 попытки останавливаются на 60 секунд или до следующего сохранения.
- Виджет работает на оверлее только если он есть в **сохранённой** раскладке. Иначе состояние «Save the layout
  in Studio».
- При обрыве потока виджет показывает «No signal, retrying» и переподключается с паузами 1, 2, 4 … 30 с; после
  переподключения до первого опорного кадра экран чёрный (у камеры владельца GOP 2 с).
- **VPN.** Если VPN-клиент гонит весь трафик в туннель, LAN-камера недоступна, и виджет честно висит в
  «No signal, retrying». Это не ошибка виджета. Лечится исключением для локальной сети в настройках VPN.
- Поддерживается H.264. H.265 даст «Unsupported codec»: переключить камеру на H.264 или другой подпоток.

## Уведомления: что нужно знать

- Лента показывает последние тосты Windows: приложение, заголовок, текст и время, новые сверху, с
  группировкой по приложениям. Новые строки подсвечены, пока не нажать «✓» на виджете (или Mark all seen в
  Plugins) — или пока уведомление не убрано из Центра уведомлений (подсветка гаснет, строка остаётся как
  история). После перезапуска приложения накопленное снова непрочитано. Бейдж у заголовка — общее число
  записей в ленте, а не число непрочитанных.
- **Первый запуск.** При первом обращении виджета Windows может запросить доступ к уведомлениям —
  разрешить. Если доступ был запрещён, вернуть его: Settings → Privacy & security → Notifications.
- Настройки (Studio → Plugins → Notifications): глубина ленты — «последние N» (10–200, по умолчанию 50)
  или «последние часы» (1–168 ч, по умолчанию 24); исключения приложений (банки, мессенджеры). Правило
  исключения — подстрока без учёта регистра; матчится и отображаемое имя приложения, и его внутренний путь
  (AUMID). При сохранении уже собранные уведомления исключённых приложений сразу вычищаются из ленты.
- Приватность: тексты уведомлений не покидают машину, не попадают в логи и никуда не сохраняются — лента
  живёт только в памяти процесса. `plugins\notify.json` — обычный JSON без секретов.
- **Честная оговорка.** Источник — официальный WinRT-листенер, но для распакованного приложения (без
  package identity) это неподдерживаемый сценарий: будущее обновление Windows может «тихо» опустошить
  ленту — виджет покажет «нет уведомлений» при выданном доступе и без ошибок. Проверить источник:
  `cargo test probe_live_listener -- --ignored --nocapture` из корня репозитория (печатает только статус,
  количество и имена приложений — не тексты). Решение и запасные пути — ADR `notifyfeed-source`
  в `docs/decisions/`.

## Где что лежит

| Что | Путь |
|---|---|
| Раскладка и темы | `%APPDATA%\io.github.gyng\widgets.json`, `themes\` |
| Настройки плагинов (зашифрованы; кроме `notify.json`) | `%APPDATA%\io.github.gyng\plugins\*.json` |
| Лог приложения | `%LOCALAPPDATA%\io.github.gyng\logs\widgetsack.log` |
| Dev-экземпляр рядом с релизом | `widgetsack.exe --multi` → конфиг в `%APPDATA%\io.github.gyng\multi\` |
| Снимок живой раскладки в репо | `.\scripts\snapshot-layout.ps1` → `examples/layouts/own-desktop.widgets.json` |
